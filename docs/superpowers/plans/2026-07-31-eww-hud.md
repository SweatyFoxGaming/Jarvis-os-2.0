# Eww Desktop HUD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small always-on-top Eww (ElKowar's Wacky Widgets) desktop overlay showing Jarvis's live status (Idle/Thinking/Executing/Error), its last 3 lines of reasoning, and the most recently touched Obsidian note — replacing the Electron window wrapper's role as "a way to glance at what Jarvis is doing" with something lighter than a full browser window.

**Architecture:** The Dockerized backend and its production deployment are **not touched** — this was explicitly descoped after investigation showed the backend has zero Electron dependency (Electron only wraps the dashboard in `desktop-electron/`, a separate app) and already runs headlessly. Migrating the whole backend to a bare-metal systemd daemon with Unix-socket IPC, as originally requested, would mean re-plumbing how it reaches Postgres/TTS/llama-cpp/whisper/the builder sandbox on a system that's live in production — confirmed with the human partner as out of scope; only the HUD ships.

Three pieces: (1) one new read-only HTTP endpoint on the **existing** Express server, reusing the port already exposed to the host — no Docker/compose changes; (2) a small standalone Node script that polls it and drives `eww update`, running on the bare host (not in Docker) since Eww needs a real X11/Wayland connection; (3) the Eww widget itself (`.yuck` + `.scss`) plus the one-time Eww build and a systemd **user** unit for the adapter script only (not a "jarvis.service" for the whole backend — that name would misleadingly imply the backend itself moved).

**Tech Stack:** TypeScript/Express (existing backend), plain Node (adapter, no framework), Eww (Rust, built from source), systemd --user.

**Investigated before writing this plan:**
- This host is a real GNOME/Wayland desktop (`XDG_SESSION_TYPE=wayland`, `gnome-shell` running) with XWayland also reachable (`DISPLAY=:1`). GNOME's Wayland compositor does not implement the `wlr-layer-shell` protocol Eww's native Wayland backend depends on for overlay positioning — so Eww will be built with its **X11 feature** and run via XWayland, which GNOME supports reliably for always-on-top, undecorated overlay windows. This is a deliberate choice, not an oversight — don't "fix" it to use the Wayland backend.
- `cargo`/`rustc` are available on this host (`/home/ubuntu/.cargo/bin/`) — Eww isn't packaged in apt/snap here, so it's built from source.
- `node`/`npm`/`curl`/`jq` are all available on the bare host (separate from the Docker container's own Node), confirmed via `which`.
- Data sources for the HUD, all already exist in the backend, none need new plumbing: `getSession(username).getState()` (in `src/cognition/session.ts`) gives `currentThought`/`executiveStatus`; `ObservationPlatform.getInstance().getDecisionTraces()` (in `src/kernel/observation.ts`) gives an array of `{reasoning, timestamp, ...}` to source the last-3-lines thought stream; `ObservationPlatform.getInstance().getAuditLogs()` gives audit-log strings (`[timestamp] Actor: X | Action: Y | Outcome: Z | Details: W`) to detect a recent `Outcome: failed` for the Error badge; `vaultRepo.listNotes(1)` (in `src/kernel/state/vault-repo.ts`) gives the most-recently-synced Obsidian note.

## Global Constraints

- No changes to `docker-compose.yml`, `Dockerfile`, or any existing route's behavior — this plan only adds one new route file and mounts it.
- The new HTTP endpoint must require the existing API-key auth (`validateApiKey`) plus a new read-only `hud.read` capability, matching this codebase's established pattern for every other dashboard-style endpoint (`reward.read`, `evolution.read`).
- `npx tsc --noEmit` and `npm test` must both pass after every task below, before that task's commit.
- The eww-adapter script and Eww config are NOT part of the Docker image or the `npm test` suite — they run on the bare host, not in the container, and are not unit-tested (there's nothing to unit test: it's a polling loop shelling out to an external binary). Verified by direct, manual observation instead (Task 5).
- Which user's session the HUD reflects is configurable via `JARVIS_HUD_USERNAME` (default `"admin"`) — a single desktop HUD reasonably shows one account's status, and `admin` matches this host's own logged-in user.

```ts
// src/interaction/routes/hud-routes.ts
import { Router } from "express";
import { validateApiKey } from "../../kernel/auth-middleware.js";
import { requireCapability } from "../../kernel/security.js";
import { getSession } from "../../cognition/session.js";
import { ObservationPlatform } from "../../kernel/observation.js";
import * as vaultRepo from "../../kernel/state/vault-repo.js";

export const hudRouter = Router();

const observation = ObservationPlatform.getInstance();
const HUD_USERNAME = process.env.JARVIS_HUD_USERNAME || "admin";
const RECENT_FAILURE_WINDOW_MS = 60_000;

// Pure and exported so it's unit-testable without a live session/DB — the
// one piece of this route with real branching logic. A recent failure
// always wins over whatever executiveStatus says, since "Jarvis thinks
// it's idle but something just failed" is exactly the case the Error badge
// exists to surface.
export function deriveHudBadge(executiveStatus: string, recentFailure: boolean): "idle" | "thinking" | "executing" | "error" {
  if (recentFailure) return "error";
  if (executiveStatus === "Executing") return "executing";
  if (executiveStatus === "Thinking" || executiveStatus === "Planning" || executiveStatus === "Reflecting") return "thinking";
  if (executiveStatus === "Idle") return "idle";
  return "idle";
}

// Audit log lines look like: "[2026-07-31T10:00:00.000Z] Actor: X | Action:
// Y | Outcome: failed | Details: Z" — cheap substring/timestamp check
// rather than a new structured error-tracking mechanism, since this is the
// only place that needs it.
function hasRecentFailure(): boolean {
  const logs = observation.getAuditLogs();
  const cutoff = Date.now() - RECENT_FAILURE_WINDOW_MS;
  for (let i = logs.length - 1; i >= 0 && i >= logs.length - 50; i--) {
    const line = logs[i];
    if (!line.includes("Outcome: failed")) continue;
    const match = line.match(/^\[([^\]]+)\]/);
    if (match && new Date(match[1]).getTime() >= cutoff) return true;
  }
  return false;
}

hudRouter.get("/api/hud/status", validateApiKey, requireCapability("hud.read"), async (req, res) => {
  try {
    const session = await getSession(HUD_USERNAME);
    const state = session.getState();
    const recentFailure = hasRecentFailure();
    const badge = deriveHudBadge(state.executiveStatus, recentFailure);

    const traces = observation.getDecisionTraces();
    const thoughtLines = traces.slice(-3).map(t => t.reasoning).filter(Boolean);

    let lastNote: { path: string; title: string } | null = null;
    try {
      const notes = await vaultRepo.listNotes(1);
      if (notes[0]) lastNote = { path: notes[0].path, title: notes[0].title };
    } catch {
      // Degrade cleanly — no live Postgres shouldn't break the rest of the HUD.
    }

    res.json({
      badge,
      statusLabel: state.executiveStatus,
      thoughtLines,
      lastNote,
    });
  } catch (err: any) {
    res.status(500).json({ badge: "error", statusLabel: "Unavailable", thoughtLines: [], lastNote: null, error: "Failed to load HUD status." });
  }
});
```

- [ ] **Step 1: Write the script**

```ts
// src/system/eww-adapter.ts
//
// Runs on the bare host (NOT inside Docker — Eww needs a real X11/Wayland
// connection the container doesn't have). Polls the backend's HUD status
// endpoint over the port already exposed to the host by docker-compose
// (no new IPC surface) and pushes each field into the running `eww`
// daemon via `eww update`. Deliberately dependency-free (only Node
// built-ins: fetch, child_process) so it runs with plain `node
// eww-adapter.js` on the host — no project node_modules required.

import { execFile } from "child_process";

const POLL_INTERVAL_MS = 2000;
const STATUS_URL = process.env.JARVIS_HUD_URL || "http://localhost:3000/api/hud/status";
const API_KEY = process.env.JARVIS_API_KEY || "";

function ewwUpdate(pairs: Record<string, string>): void {
  const args = ["update", ...Object.entries(pairs).map(([k, v]) => `${k}=${v}`)];
  execFile("eww", args, (err) => {
    if (err) {
      // eww not running yet / window not open — this is expected before
      // `eww open jarvis-hud` has been run, and on every restart of the
      // eww daemon itself. Log once per failure, keep polling; don't crash
      // the adapter over a transient external-process error.
      console.error(`[eww-adapter] eww update failed: ${err.message}`);
    }
  });
}

async function pollOnce(): Promise<void> {
  try {
    const res = await fetch(STATUS_URL, {
      headers: API_KEY ? { "X-API-Key": API_KEY } : {},
    });
    if (!res.ok) {
      ewwUpdate({ jarvis_badge: "error", jarvis_status: "Unreachable", jarvis_thought: "HUD endpoint returned an error.", jarvis_note: "" });
      return;
    }
    const data = await res.json();
    ewwUpdate({
      jarvis_badge: data.badge || "idle",
      jarvis_status: JSON.stringify(data.statusLabel || ""),
      jarvis_thought: JSON.stringify((data.thoughtLines || []).join("\\n")),
      jarvis_note: JSON.stringify(data.lastNote ? data.lastNote.title : "None yet"),
    });
  } catch (err: any) {
    ewwUpdate({ jarvis_badge: "error", jarvis_status: "Unreachable", jarvis_thought: JSON.stringify(`Cannot reach Jarvis: ${err.message}`), jarvis_note: "" });
  }
}

let stopped = false;
async function loop(): Promise<void> {
  while (!stopped) {
    await pollOnce();
    await new Promise(r => setTimeout(r, POLL_INTERVAL_MS));
  }
}

function shutdown(signal: string): void {
  console.error(`[eww-adapter] received ${signal}, stopping.`);
  stopped = true;
  process.exit(0);
}
process.on("SIGINT", () => shutdown("SIGINT"));
process.on("SIGTERM", () => shutdown("SIGTERM"));

loop();
```

Note: `jarvis_status`/`jarvis_thought`/`jarvis_note` are wrapped in `JSON.stringify(...)` before being passed as `eww update` arguments — this is deliberate, not a bug: it's the simplest reliable way to shell-escape arbitrary text (quotes, newlines, special characters in a thought string or note title) into a single shell argument that yuck's string literal parsing will read back correctly, since `JSON.stringify` on a string produces a properly quoted-and-escaped string literal. Do not "simplify" this to raw string interpolation.

- [ ] **Step 1: Write `scripts/install-eww.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail
# Builds eww from source with the X11 feature — GNOME's Wayland compositor
# doesn't implement wlr-layer-shell, which eww's native Wayland backend
# needs for overlay positioning, so X11-via-XWayland is the reliable path
# on this specific host. Requires cargo/rustc (already present).
EWW_DIR="${HOME}/.local/src/eww"
mkdir -p "$(dirname "$EWW_DIR")"
if [ ! -d "$EWW_DIR" ]; then
  git clone https://github.com/elkowar/eww.git "$EWW_DIR"
fi
cd "$EWW_DIR"
git pull --ff-only
cargo build --release --no-default-features --features x11
mkdir -p "${HOME}/.local/bin"
cp target/release/eww "${HOME}/.local/bin/eww"
echo "Installed eww to ${HOME}/.local/bin/eww — ensure that directory is on your PATH."
```

- [ ] **Step 2: Write `deploy/jarvis-hud.service`**

```ini
[Unit]
Description=Jarvis OS desktop HUD adapter (eww bridge)
After=graphical-session.target
```

- [ ] **Step 3: Write `scripts/deploy-hud.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail
# Compiles the adapter to plain JS (no project node_modules needed at
# runtime — see eww-adapter.ts's own header comment) and installs the
# systemd --user unit. Does NOT touch the Docker-based backend/deployment
# in any way.
REPO_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DEST_DIR="${HOME}/jarvis-hud"
mkdir -p "$DEST_DIR"

npx tsc --module nodenext --target es2022 --moduleResolution nodenext \
  "$REPO_DIR/src/system/eww-adapter.ts" --outDir "$DEST_DIR"

mkdir -p "${HOME}/.config/systemd/user"
cp "$REPO_DIR/deploy/jarvis-hud.service" "${HOME}/.config/systemd/user/jarvis-hud.service"

systemctl --user daemon-reload
systemctl --user enable jarvis-hud.service
systemctl --user restart jarvis-hud.service

echo "Deployed. Check status: systemctl --user status jarvis-hud.service"
echo "Open the HUD window with: eww open jarvis-hud --config $REPO_DIR/config/eww"
```
